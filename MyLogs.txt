PROJECT LOG

Project goal
This project is for a low altitude drone that flies in cities at about truck height.
The drone needs to understand what is around it so it can avoid objects safely.
The first phase of the project is to build a semantic segmentation model using the Cityscapes fine annotation dataset.

Dataset plan
The dataset folder is `gtFine_trainvaltest`.
The `gtFine_trainvaltest\gtFine\test` folder contains black images (privacy), so it will not be used.

Partitioning (finalized)
- Training: use the entire `gtFine_trainvaltest\gtFine\train` folder.
- Validation: use the first half of the `gtFine_trainvaltest\gtFine\val` folder.
- Testing: use the second half of the `gtFine_trainvaltest\gtFine\val` folder.

Note: These three partitions are disjoint — no image appears in more than one partition.

Phase 2 — Baseline FCN-ResNet50 (completed 2026-05-14)
Source files: `src/cityscapes_dataset.py`, `src/metrics_logger.py`, `src/train_baseline.py`

Training configuration (matched to YOLO for fair comparison):
- Model: FCN-ResNet50 (pretrained=False, 19 classes)
- Train subset: 400 images
- Val subset: 100 images
- Input size: 512x512
- Batch size: 4
- Epochs: 5
- Optimizer: SGD (lr=1e-3, momentum=0.9, weight_decay=1e-4)
- Loss: CrossEntropyLoss (ignore_index=255)
- Run number: 3

Results:
- Final val mIoU: 0.3329
- Average inference latency (100 val images, GPU-sync'd forward-pass only): 39.60 ms
- Total training time: 278.25 seconds
- Checkpoints: `runs/phase2_baseline_run3/resnet50_Run3_Epoch{1-5}.pth`

Latency measurement methodology:
- Image loaded and preprocessed OUTSIDE the timed window.
- `torch.cuda.synchronize()` called before and after the model forward pass.
- Latency = net GPU forward-pass time only (no I/O, no pre/post processing).

Phase 3 — YOLOv8-Seg Edge Model (completed 2026-05-14)
Source files:
  - `src/yolo_cityscapes_utils.py` — Cityscapes label helpers and polygon normalization
  - `src/prepare_yolo_cityscapes.py` — converts JSON polygons to YOLO .txt format
  - `src/train_yolo.py` — YOLO training entrypoint and CSV logging
  - `src/append_yolo_metrics.py` — maps Ultralytics results.csv into the shared CSV
  - `src/trim_yolo_dataset.py` — trims the YOLO dataset to a fixed sample count
  - `src/yolo_latency_fixed.py` — correct GPU-sync'd latency benchmark (no NMS)
  - `src/visual_grid.py` — generates 1x4 comparison grid (Raw, GT, ResNet50, YOLO)
  - `cityscapes_trimmed.yaml` — YOLO dataset config for 400-sample trimmed subset

Training configuration (matched to ResNet50 for fair comparison):
- Model: yolov8n-seg.pt (Nano, instance segmentation)
- Train subset: 400 images (via yolo_cityscapes_trimmed)
- Val subset: 400 images
- Input size: 512x512
- Batch size: 4
- Epochs: 5
- Device: GPU (RTX 3060)

YOLO dataset structure:
- `yolo_cityscapes_trimmed/images/train` and `val` are Windows directory junctions
  pointing to the original Cityscapes images (no duplication of 50 GB image set).
- `yolo_cityscapes_trimmed/labels/train` and `val` contain generated YOLO polygon .txt files.

Results:
- Val Mask mAP50 (Epoch 1 → Epoch 5): 0.0641 → 0.1051
- Weights: `runs/segment/runs/segment/train_trimmed/weights/best.pt`

Latency measurement methodology:
- Images loaded and preprocessed OUTSIDE the timed window.
- `model.model(tensor)` called (raw PyTorch backbone, NO NMS, NO Ultralytics wrapper).
- `torch.cuda.synchronize()` called before and after the forward pass.
- 5 GPU warm-up passes run before measurement begins.
- This matches the ResNet50 measurement methodology exactly for a fair comparison.

Latency results (100 validation images, GPU-sync'd forward-pass only):
- YOLOv8n-seg: 13.84 ms
- FCN-ResNet50: 39.60 ms
- Comparison: YOLO is 2.86x faster than ResNet50.
